VIBECAM
Remotion Video Editor
Engineering Build Prompt — For Antigravity
  v2.0       Remotion 4       Next.js 14       Supabase  
MISSION BRIEF
Replace VibeCam’s basic start/end trim editor with a full-featured, Remotion-powered non-linear video editor — embedded directly in the browser. Users should feel like they’re using a lightweight version of ScreenStudio or Descript, not a slider. Everything renders in React, exports via Remotion’s Lambda renderer or WASM encoder, and integrates with the existing Supabase + Cloudflare R2 storage stack.

1. Context & What You Are Building
1.1 Where We Are Now
VibeCam v1 is a browser-based screen recorder with a minimal editing UI consisting of:
A single timeline track with two drag handles (trim start, trim end)
A basic video player for preview
A Share button that stores the recording locally or uploads to Cloudflare R2
This is intentionally minimal for v1. It ships fast and gets users recording. But power users immediately ask for more: cutting dead silence out of the middle, adding a title card, zooming in on a UI element, annotating with text. v1 cannot do any of this.
1.2 What You Are Building
A fully embedded, Remotion-powered video editor that replaces the v1 trim panel. The editor lives at the /edit route in the Next.js app and receives a recording (from localStorage or R2). The user edits their recording using a rich timeline UI, previews the result in real time via Remotion's Player component, and exports a final rendered MP4.
Think of it as: Loom’s simplicity × Remotion’s rendering power × VibeCam’s dark aesthetic.
1.3 Why Remotion
Remotion renders video using React components — every edit is a React state change, not a video manipulation library
The @remotion/player package gives a real-time interactive preview with frame-accurate scrubbing at zero cost
Remotion Lambda can render a final MP4 in the cloud server-side in seconds, no ffmpeg.wasm needed
Remotion Compositions are just React — adding a title card or zoom effect is a new React component, not a ffmpeg filter
Remotion has first-class TypeScript support and an active ecosystem of community compositions

3. Remotion Architecture
3.1 The Main Composition
Everything the user edits maps to a single Remotion Composition called <VibeCamComposition>. This is the source of truth for the rendered video.
// remotion/VibeCamComposition.tsx
export const VibeCamComposition: React.FC<CompositionProps> = ({
  clips,          // VideoClip[]
  overlays,       // Overlay[]
  effects,        // Effect[]
  audioTracks,    // AudioTrack[]
  intro,          // IntroConfig | null
  outro,          // OutroConfig | null
  fps,            // number (default 30)
  width,          // number (default 1920)
  height,         // number (default 1080)
}) => {
  return (
    <AbsoluteFill>
      {intro && <Sequence durationInFrames={intro.durationFrames}><IntroSequence {...intro} /></Sequence>}
      {clips.map(clip => <Sequence key={clip.id} from={clip.startFrame} durationInFrames={clip.durationFrames}><VideoClip {...clip} /></Sequence>)}
      {overlays.map(o => <Sequence key={o.id} from={o.startFrame} durationInFrames={o.durationFrames}><OverlayElement {...o} /></Sequence>)}
      {effects.map(e => <Sequence key={e.id} from={e.startFrame} durationInFrames={e.durationFrames}><EffectLayer {...e} /></Sequence>)}
      {outro && <Sequence from={totalDurationFrames - outro.durationFrames}><OutroSequence {...outro} /></Sequence>}
    </AbsoluteFill>
  );
};

3.3 State Management
Use Zustand for the editor store. The store is the single source of truth for CompositionProps. Every user action (drag clip, add text, change speed) dispatches a store action that updates CompositionProps. Remotion Player re-renders automatically because it receives CompositionProps as inputProps.
// store/useEditorStore.ts
type EditorStore = {
  compositionProps: CompositionProps;
  selectedClipId: string | null;
  selectedOverlayId: string | null;
  playheadFrame: number;
  zoom: number;                 // timeline zoom level 1–10
  isPlaying: boolean;
  history: CompositionProps[];  // for undo/redo
  historyIndex: number;

  // actions
  addClip: (clip: VideoClip) => void;
  splitClip: (clipId: string, atFrame: number) => void;
  deleteClip: (clipId: string) => void;
  addOverlay: (overlay: Overlay) => void;
  updateOverlay: (id: string, props: Partial<Overlay>) => void;
  deleteOverlay: (id: string) => void;
  addEffect: (effect: Effect) => void;
  setPlayheadFrame: (frame: number) => void;
  undo: () => void;
  redo: () => void;
};

3.4 Undo / Redo
Every action that mutates CompositionProps must push the previous state onto history[]
history is capped at 50 entries to prevent memory bloat
Undo pops the last entry and applies it; Redo re-applies
Ephemeral actions (playhead scrub, timeline scroll) do NOT push to history
Use Immer inside Zustand for ergonomic immutable updates: set(produce(state => { state.compositionProps.clips.push(clip) }))

9. Critical Implementation Notes for Antigravity
Must-know Remotion specifics
useCurrentFrame() only works inside a Remotion composition tree — not in regular React components. Never call it outside a Remotion <Composition> or <Player>.
The Remotion Player is a client-side component. Add "use client" to PreviewPanel.tsx. If using Next.js App Router, wrap the Player in a dynamic import with ssr: false.
Remotion uses a concept of "durationInFrames" not seconds. All timing in CompositionProps must be stored in frames. Use a helper: const toFrames = (sec, fps) => Math.round(sec * fps). Store fps in the Zustand store; default to 30.
interpolate() clamps by default (extrapolateLeft/Right: "clamp"). For zoom effects, always use extrapolateLeft: "clamp", extrapolateRight: "clamp" to prevent values going out of bounds.
spring() in Remotion is frame-based, not time-based. It takes { frame, fps, config } not a duration. For consistent animations across different fps values, always pass fps from the store.
Video sources inside a Remotion composition must be accessible URLs. For local recordings in v1 (ObjectURL), create a temporary Blob URL and pass it. For cloud recordings, pass the R2 CDN URL directly.
@remotion/player does not support seeking to a specific frame imperatively via ref in older versions. Use the playerRef.current.seekTo(frame) method added in Remotion 4. Ensure the package is v4+.
When using Lambda rendering, the Remotion site (the webpack bundle of your compositions) must be deployed separately with npx remotion lambda sites create. The site URL is passed to renderMediaOnLambda as serveUrl. This is a one-time deploy step; update it when compositions change.
Performance rules
Wrap ClipBlock in React.memo with a custom comparator that only re-renders when the clip's own data changes. Without this, dragging the playhead re-renders every clip on every frame.
Waveform SVG path calculation is expensive. Compute it once in useWaveform() with useMemo and cache by clip src URL.
The Properties Panel re-renders on every store change. Use Zustand's selector pattern: const selectedClip = useEditorStore(s => s.compositionProps.clips.find(c => c.id === s.selectedClipId)) to subscribe only to relevant state.
Do not put the full history[] array in a single Zustand subscription — this causes re-renders on every undo. Keep history in a separate slice or use a ref.
Design rules
All editor UI must use the VibeCam design system: --bg #0A0A0B, --surface #111113, --accent #E8FF47, Syne font for labels, Geist Mono for timecodes and values.
The timeline is always dark. No light mode. This is a creative tool and dark mode is the only mode.
All interactive controls (drag handles, clip blocks, toolbar buttons) must have a clear focus ring for keyboard navigation accessibility.
Every panel resize must be smooth. Use CSS transitions or Framer Motion for layout animations. Janky panel snapping destroys the professional feel.
Export button must always be visible and never disabled. If the user clicks Export with an empty composition, show a helpful error in the modal, not a disabled button state.
Do not build (out of scope for this sprint)
Multi-user / collaborative editing
Version history / recording revision system
Custom font upload
Video transitions between clips (crossfade, wipe) — flag for v3
Mobile editor (responsive editing UI) — show a "use desktop" message on viewports < 1024px
AI-powered editing suggestions
Captions / Whisper transcription — architecture for it, but no UI yet


10. Definition of Done
This sprint is complete when all of the following are true:
A user can open an existing VibeCam recording in the editor at /edit/[id]
The Remotion Player renders the recording with correct playback
The timeline shows the video clip and the user can trim, split, and delete clips
The user can add a text overlay, position it in the frame, set its duration on the timeline, and see it in the preview
The user can add a zoom effect to any portion of the video and see it animate in the preview
The user can add a blur/redaction region to any portion of the video
The user can add an intro sequence with a custom title
All keyboard shortcuts in Section 2.1 work correctly
Undo and redo work for all mutation actions
The user can click Export, see a progress bar, and receive a downloadable MP4 link
The exported MP4 includes all edits: clips, overlays, zoom effects, intro
The editor feels fast: no visible lag when dragging the playhead or moving clips

Ship the timeline first. Everything else is an overlay on top of a working timeline.
The zoom effect and text overlays are the two features users will demo in their first five minutes. Make those two feel magical and the rest will follow.
